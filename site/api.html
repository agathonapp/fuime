The blast radius

A key cannot name a business.

Which business a request acts on is read off the key and nothing else. There is no business id in any route or any body here, so there is no request a stolen key can be talked into making against somebody else's venture.

The key is the business

There is no field to set and therefore no field to forge. The limit is a property of the shape of the API rather than a permission somebody remembered to switch off, which is why it holds even when everything else has gone wrong.

It asks for money. It cannot move money

A key creates payment links and takes them down. There is no endpoint that pays anything out, sends anything anywhere, or changes where a payout goes. Those live behind a human approval that no key can reach.

It cannot read the ledger

No transactions, no receipts, no year-to-date totals. A leaked key tells whoever holds it what the business is called and whether it can currently sell. It tells them nothing about what the business has earned.

It cannot see a person

No names, no email addresses, no ages, no guardian record. The /me endpoint reports whether a venture can sell without reporting why, because the program asking may be running on a stranger's server.

The whole surface

Three endpoints, and that is all of them.

Path Method What it does
/api/fuime/v1/me GET Whose key this is, and whether it can sell today
/api/fuime/v1/payment_links GET The live links this key made, newest first
/api/fuime/v1/payment_links POST Make one, $1 to $10,000, USD
/api/fuime/v1/payment_links/:id DELETE Take one down

A key only sees and only deletes the links it made itself, so one key cannot take down another key's links or the storefront your customers already have open. A misplaced decimal point on a create is refused outright rather than clamped to the maximum. A deleted link stops taking money and the record survives, because a sold link is named on somebody's receipt.

The limits

Five numbers you will actually hit.

Keys cost nothing and are not a plan feature. The caps below are safety, not billing: every one of them exists because of a failure somebody has already had.

Every key starts with this prefix

Prefixed the way Stripe and GitHub prefix theirs, so a secret scanner can match it. A key pasted into a public repository can be found and killed by machine before a person notices it is gone.

fuime_sk_

Live keys per business

Not a resource limit. Three integrations is already more than most businesses have, and an account collecting dozens is either confused or compromised. The cap makes the second case visible while it is still small.

10

Live links per key

The expected failure here is a program stuck in a retry loop, not an attacker. This is what stops one from filling a dashboard with ten thousand rows overnight. Take some down and you can make more.

250

Requests a minute

Per key, across all three endpoints. Enough for an agent answering customers in a conversation, and not enough for a loop nobody is watching.

120

Times you will be shown the key

The plaintext is never stored. It is encrypted at rest and indexed blind, so the only copy that has ever existed in readable form is the one on your screen when you mint it. Lose it and you mint another.

Once

What is missing

Four things this API does not have.

Paddle and Stripe both ship all four. fuime does not, and finding that out from a page is cheaper than finding it out from a build.

No separate practice environment

Every key is a live key and every link it makes is a real link that will charge a real card. Make one for a dollar, look at it, then delete it.

No client libraries

Nothing to install in any language. It is JSON over HTTPS and whatever your language already does with that, which for three endpoints is usually less work than a library would be.

Nothing calls your server back

There are no outbound webhooks, so nothing tells your code when a link gets paid. You poll the list, or you watch the ledger in the app. This is the gap we hear about most.

No machine-readable spec

There is no OpenAPI document to generate a client from. This page and the Developer section of your venture's settings are the documentation, and the three routes above are the contract.
